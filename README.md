# TgP — парсер Telegram-источников заказов по контенту/SMM

Ищет **активные** (посты не старше 24 часов) публичные Telegram-каналы и чаты,
где публикуют заказы/вакансии по темам:

- видеомонтаж
- reels / TikTok / Shorts
- motion design
- SMM / ведение соцсетей
- креативы для соцсетей

и отсеивает спам и нерелевантный контент. Цель по умолчанию — 150 каналов и
30 чатов (настраивается, см. `TARGET_CHANNELS`/`TARGET_CHATS`).

**Результаты накапливаются между запусками.** Каждый повторный запуск сперва
перепроверяет источники из предыдущего `out/report.json` (ещё активны и
релевантны? тогда остаются) и только потом ищет новые — так что просто
**запускайте парсер повторно** (например, на следующий день), чтобы список
пополнялся, а не начинался с нуля. Так и стоит добирать до 100+ каналов,
если за один прогон столько не набралось — это ожидаемо, у поиска Telegram
есть свои пределы на один запуск (см. "Ограничения" ниже).

## Как это работает

0. **Перепроверка предыдущего результата** — если в `out/report.json` уже
   что-то есть с прошлого запуска, парсер сначала заново проверяет именно
   эти источники (ещё активны? всё ещё релевантны?) и уже потом идёт искать
   новые. Так список растёт от запуска к запуску, а не сбрасывается.
1. **Поиск** (`tgparser/search.py`) — прогоняет по каждой теме несколько
   широких терминов (например, "видеомонтажер", "ведение соцсетей") через
   **полнотекстовый глобальный поиск Telegram** (`messages.searchGlobal` —
   тот же API, что и строка поиска в приложении). Специально не сужаем
   запрос до фраз вида "видеомонтажер вакансия" — по одному слову находится
   уже всё, что нашлось бы и по узкой фразе, и больше; отсекать нерелевантное
   — задача следующего шага (анализа), а не формулировки запроса. Поиск идёт
   отдельно по каналам и по чатам (группам), с пагинацией.
2. **Seed-список** (`seeds.txt`, опционально) — источники, которые вы уже
   нашли сами (например, в каталоге TGStat/Telega.in) и хотите гарантированно
   проверить — они добавляются к кандидатам напрямую.
3. **Анализ** (`tgparser/analyzer.py`) — для каждого кандидата:
   - проверяет дату последнего сообщения (активность за последние N часов,
     по умолчанию 24);
   - забирает последние сообщения и прогоняет через фильтр релевантности
     (`tgparser/filters.py`): пост должен упоминать тему **и** содержать
     признак заказа/вакансии (`ищем`, `вакансия`, `оплата`, `заказ`,
     `фриланс` и т.п.) **или** упоминание цены/валюты (`500₽ за ролик`);
   - отбрасывает спам (заработок без вложений, розыгрыши, крипта и т.д.)
     и авто-сообщения ботов о новых участниках ("Hi @user, welcome to my
     group") — раньше они ложно засчитывались как заказы из-за повторения
     названия канала в тексте;
   - если релевантных постов не нашлось — источник отбрасывается.
4. **"Снежный ком"** — после основного поиска парсер сканирует **все**
   сообщения (не только релевантные примеры, а всю прочитанную историю
   каждого источника — до `MESSAGES_PER_CHAT` штук) на предмет публичных
   `t.me/...`-ссылок на другие каналы/чаты и проверяет их тоже. Это и
   отвечает на "посмотреть, что там за ссылки внутри чатов" — именно так
   это и происходит. Повторяется до `SNOWBALL_MAX_ROUNDS` раз (по
   умолчанию 25) или пока не наберётся целевое количество — на практике
   это и превращает пятиминутный прогон в многочасовой: чем больше
   источников подтверждено, тем больше новых ссылок находится на
   следующем раунде.
5. **Вступление в закрытые для чтения чаты** (`AUTO_JOIN_CHATS`) — если
   сообщения чата не читаются без вступления, парсер сам вступает (в
   пределах `MAX_JOINS_PER_RUN`), чтобы прочитать историю. Если же чат
   требует **одобрения заявки** администратором — вступать не пытается
   (одобрения всё равно не дождаться в моменте), а просто присылает вам
   ссылку в отдельный раздел "Требуют заявки на вступление" — разбираться
   дальше вручную.
6. **Уведомления в реальном времени** — как только источник подтверждён
   (или найден чат, требующий заявки), ссылка на него сразу отправляется
   вам в Telegram "Избранное" (Saved Messages), не дожидаясь конца всего
   прогона. Источники, уже известные с прошлых запусков, повторно не
   присылаются — только то, что нашлось впервые.
7. **Отчёт** (`tgparser/report.py`) — итог сохраняется в `out/report.md`
   (разделы "Каналы", "Чаты" и "Требуют заявки на вступление",
   человекочитаемо) и `out/report.json` (для дальнейшей обработки):
   ссылка, тип, описание, число подписчиков, дата последней активности,
   совпавшие темы, примеры релевантных постов со ссылками.

Ключевые слова и поисковые фразы редактируются в `tgparser/keywords.py`
(легко добавить новые темы/формулировки).

## Установка

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

Заполните `.env`:

1. **API-доступ к Telegram**: зайдите на https://my.telegram.org, создайте
   приложение и возьмите `api_id` / `api_hash` → впишите в `TG_API_ID` /
   `TG_API_HASH`.
2. **VPN-прокси** (если Telegram недоступен напрямую, например из РФ):
   в `.env` уже прописаны параметры под локальный SOCKS5 от Happ:
   ```
   PROXY_TYPE=socks5
   PROXY_HOST=127.0.0.1
   PROXY_PORT=10808
   ```
   Убедитесь, что Happ (или другой VPN-клиент с локальным SOCKS5) запущен
   перед стартом парсера. Если прокси не нужен — удалите/очистите эти
   переменные.

(Необязательно) скопируйте `seeds.txt.example` в `seeds.txt` и впишите туда
каналы/чаты, которые вы уже нашли вручную — парсер их тоже проверит.

## Запуск

```bash
python -m tgparser.main search
```

**На Windows** можно вместо этого просто дважды кликнуть `run.bat` в папке
проекта (или запустить его из `cmd`) — он сам активирует `.venv` и запустит
поиск, не нужно вводить команды вручную каждый раз.

При первом запуске Telegram запросит вход: номер телефона, код из
приложения/SMS и, если включена двухфакторная аутентификация — пароль.
После успешного входа создаётся файл сессии (`tgp_session.session`,
имя настраивается через `TG_SESSION_NAME`) — при повторных запусках
повторный вход не требуется.

Полный прогон (поиск + анализ каждого кандидата + до 25 раундов "снежного
кома" по ссылкам) может занять от нескольких минут до нескольких часов —
зависит от того, насколько много связанных источников найдётся по цепочке
ссылок в вашей нише, останавливается сам, как только годных ссылок больше
не остаётся, или сработает `MAX_RUNTIME_MINUTES`. Это нормально, в логе
видно прогресс по каждому найденному источнику, а в Избранное они
прилетают сразу же, не дожидаясь конца.

Результат:

```
out/report.md    — читаемый отчёт (разделы "Каналы" и "Чаты")
out/report.json  — тот же результат в JSON
```

## Настройки (`.env`)

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `ACTIVE_WINDOW_HOURS` | 24 | Источник считается активным, если есть пост не старше этого числа часов |
| `MESSAGES_PER_CHAT` | 150 | Сколько последних сообщений разбирать в каждом источнике |
| `MAX_PAGES_PER_QUERY` | 10 | Сколько "страниц" результатов брать на каждую поисковую фразу |
| `REQUEST_DELAY_SECONDS` | 1.5 | Пауза между запросами к Telegram (защита от FloodWait/бана) |
| `TARGET_CHANNELS` | 150 | Сколько каналов набрать, прежде чем останавливаться |
| `TARGET_CHATS` | 30 | Сколько чатов набрать, прежде чем останавливаться |
| `CONCURRENCY` | 5 | Сколько кандидатов анализировать параллельно |
| `SNOWBALL_MAX_ROUNDS` | 25 | Сколько раундов "снежного кома" по ссылкам делать после основного поиска |
| `MAX_RUNTIME_MINUTES` | 360 | Потолок по общему времени прогона (не цель — останавливается раньше сам, если нашёл всё, что мог); поставьте 600 для ~10 часов |
| `SEEDS_FILE` | seeds.txt | Файл с вручную добавленными кандидатами (см. `seeds.txt.example`) |
| `NOTIFY_SAVED_MESSAGES` | true | Слать найденный источник в Избранное сразу же |
| `AUTO_JOIN_CHATS` | true | Вступать в чаты, если это единственный способ прочитать сообщения (не для тех, что требуют одобрения заявки) |
| `JOIN_DELAY_SECONDS` | 8 | Отдельная (более осторожная) пауза именно между вступлениями |
| `MAX_JOINS_PER_RUN` | 150 | Максимум вступлений за один прогон — предохранитель для аккаунта |
| `OUTPUT_DIR` | out | Куда сохранять отчёты |

## Ограничения

- Парсер видит только **публичные** каналы/чаты (есть username/ссылка) —
  полностью приватные группы без публичной ссылки не анализируются, и в
  них парсер не вступает (нечем — у него нет инвайт-ссылки).
- У глобального поиска Telegram (`messages.searchGlobal`) есть свои
  внутренние ограничения на глубину/объём выдачи на один запрос — это
  ограничение платформы, а не парсера. Поэтому для по-настоящему большого
  охвата в ход идут несколько механизмов сразу: широкий набор поисковых
  терминов, seed-список и глубокий "снежный ком" по ссылкам из полной
  истории сообщений — если после всего этого целевое количество не
  набралось, лог явно скажет, на каком этапе кандидаты закончились. Сколько
  реально займёт прогон (несколько минут или несколько часов) целиком
  зависит от того, насколько богат граф ссылок в вашей нише — это не
  подкручивается искусственно.
- **Авто-вступление в чаты** (`AUTO_JOIN_CHATS=true`) — реальное действие
  на вашем аккаунте: парсер остаётся участником каждого такого чата после
  прогона (не выходит автоматически), и это может засветить активность как
  массовое вступление в глазах анти-спам систем Telegram при слишком
  агрессивных настройках. `JOIN_DELAY_SECONDS` и `MAX_JOINS_PER_RUN` — это
  ограничители именно под этот риск; не отключайте их совсем и не ставьте
  `JOIN_DELAY_SECONDS` слишком маленьким. Если не хотите, чтобы парсер сам
  вступал куда-либо — поставьте `AUTO_JOIN_CHATS=false`, тогда такие чаты
  просто не попадут в отчёт (в отличие от чатов с заявкой на вступление,
  которые всегда попадают в отдельный раздел со ссылкой).
- Telegram может отвечать `FloodWaitError` при слишком частых запросах —
  парсер сам ждёт нужное время и продолжает. Не уменьшайте
  `REQUEST_DELAY_SECONDS`/не увеличивайте `CONCURRENCY` слишком агрессивно,
  чтобы не словить временное ограничение аккаунта.
- Качество списка зависит от поисковых терминов и ключевых слов в
  `tgparser/keywords.py` — при необходимости расширяйте/уточняйте их под
  свою нишу.
